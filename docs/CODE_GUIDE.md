# Как устроен код (чтобы вы могли объяснить любую часть)

Если сайт показывают клиенту или работодателю, спросят «а как это работает». Эта шпаргалка нужна, чтобы отвечать уверенно и править без страха.

## Главная мысль
Сайт делится на **данные** и **отрисовку**. Тексты и список работ лежат в одном файле (`data/site.js`), а скрипт (`js/portfolio.js`) читает их и собирает страницы. Поэтому, чтобы поменять текст или добавить работу, не нужно трогать вёрстку.

## Структура папок и зачем каждая

| Что | Зачем |
|---|---|
| `index.html`, `project.html` | Каркас страниц: шапка, пустые секции, подвал. Содержимое подставляет скрипт |
| `data/site.js` | Все тексты, работы, контакты. Это единственный файл, который вы правите в обычной жизни |
| `css/portfolio.css` | Дизайн: цвета (переменные в начале), сетки, кнопки, секции, тёмная и светлая темы |
| `css/fx.css`, `js/fx.js` | Эффекты поверх: курсор, частицы, шторка. Можно отключить, не сломав сайт |
| `сайт_1`, `сайт_2` | Две демо-работы. У каждой общий `css/base.css` (исходный стиль), `css/pages.css` (общие компоненты) и `js/app.js` (мелкие помощники) |

## Как именуются классы
В портфолио принят подход **БЭМ** (блок, элемент, модификатор):
- `work` — блок, `work__title` — его часть, `btn--accent` — вариант;
- один блок = одна карточка/секция, элементы пишутся через `__`, варианты через `--`.

В демо-работах классы короче и по смыслу: `.panel`, `.metric-card`, `.badge`, `.chip`. Это нормально, в небольших проектах так и делают.

Единые правила, которых стоит держаться при правках:
1. Названия по-английски, строчными, через дефис.
2. Класс называется по тому, **что это**, а не как выглядит (`.badge`, а не `.green-pill`).
3. Цвета и размеры берутся из переменных `--accent`, `--bg-panel`, `--radius`, а не пишутся числами по месту.
4. Отступ в файлах: 2 пробела (в исходных страницах работ там, где 4, не переделывайте, зачем).

## Как это работает по шагам (для объяснения)
1. Браузер открывает `index.html` и подтягивает `data/site.js`, затем `js/portfolio.js`.
2. Скрипт берёт тексты по ключам: в разметке стоит `data-t="hero.status"`, скрипт находит `SITE.hero.status` и подставляет.
3. Карточки работ создаются циклом по `SITE.projects`. Превью: если есть скриншот `work-*.webp`, берётся он, иначе в карточку вставляется уменьшенная живая страница (`iframe`, масштаб считается из ширины блока).
4. Страница кейса одна на все работы: `project.html?p=storecrm`. Скрипт читает `p` из адреса, находит работу и рисует её.
5. Тема хранится в `localStorage` и ставится атрибутом `data-theme` на `<html>` ещё до отрисовки, чтобы страница не мигала.
6. Доступность: у вкладок роли `tab`/`tabpanel`, стрелки переключают их, есть «пропустить к содержимому», живая область для объявлений, уважается `prefers-reduced-motion`.

## Что говорить, если спросят про ИИ
Использовать ИИ при разработке сейчас нормально, этим пользуются почти все. Но вам нужно уметь:
- объяснить, как устроена любая часть (шпаргалка выше);
- внести правку без помощи со стороны;
- ответить, **почему** выбрано именно так.

Лучшая подготовка: откройте `data/site.js` и поменяйте тексты, потом добавьте пробную работу по инструкции из `docs/BUILD.md`, потом поменяйте цвет в `css/portfolio.css` и посмотрите на результат. Часа хватит, чтобы чувствовать сайт своим. Если спросят прямо, честный ответ «часть кода писал с помощью ИИ, архитектуру и правки веду сам» работает лучше любой попытки скрыть.
